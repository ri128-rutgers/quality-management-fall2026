Software-intensive systems

▶ Interactive lectureOpen notebook in ColabDue Nov 4: Simulation labSubmit in Canvas

Learning objectives

  • Size software with source lines of code and function points and estimate effort with COCOMO II, including scale factors and cost drivers.
  • Adapt effort estimation to agile delivery (story-point velocity, throughput) and to ML development, where data work dominates coding.
  • Estimate sustainment cost for software using change-traffic and defect-density approaches.

Lecture segments

1. Sizing and COCOMO II

Effort grows a little faster than size, and a handful of drivers (team capability, reuse, required reliability, schedule pressure) multiply it; that is COCOMO II in one sentence, and the formula is in the workbook. The practical points: calibration to your own history, the cone of uncertainty, and what to do when you have no history.

2. Agile and ML development cost

Velocity-based forecasting, and the empirical finding that in ML projects the majority of effort is data acquisition, cleaning, labeling, and evaluation rather than model code. Costing the data pipeline as a first-class element.

3. The ML development lifecycle as a cost object

Data-centric development, experiment tracking, feature stores, model registries, CI/CD for models, and monitoring. Each MLOps stage is a recurring cost element; we map the lifecycle to the CES and estimate the sustainment share attributable to retraining pipelines versus application code.

4. Software sustainment

Annual change traffic, technical-debt interest, dependency and security patch cadence, and the sustainment burden of model dependencies (framework and API deprecations).

Quality management lens

Software quality economics. Defect density, defect removal efficiency, and Boehm's COQUALMO extension to COCOMO II tie quality practices to effort. For ML, the ML Test Score rubric (Breck et al.) is a production-readiness checklist that doubles as an appraisal-cost inventory. Technical debt is deferred quality cost with interest.

Agentic AI corner

Agentic development tools (coding agents, autonomous test generation) change the software effort model. Discuss which COCOMO II drivers they move and in which direction; there is not yet reliable calibration data, which is itself a cost-estimating risk to document.
